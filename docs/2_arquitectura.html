Arquitectura

2.1. Panorama

Sina es una aplicación FastAPI (Python 3.12+) que sirve una SPA React y una API REST. Los precios se obtienen de fuentes de gobierno y de scraping de supermercados, se guardan en PostgreSQL 16 + pgvector, y se exponen por endpoints que consumen tanto la SPA como el agente conversacional. El historial del chat vive en MongoDB.

2.3. Patrones arquitectónicos

  • Repository Pattern. Todo el acceso a datos pasa por sina/db/repository.py: un BaseRepository[T] genérico y una subclase por modelo (GasolinaRepository, GasLPRepository, SupermercadoRepository, MunicipioRepository, CatalogoRepository, …). Centraliza consultas, upserts y caché.
  • Caché inteligente on-demand. Cada fuente decide si sus datos siguen vigentes; si no, llama a la fuente, guarda y responde (ver Datos e Ingesta).
  • Providers abstractos. LLM y embeddings detrás de una ABC + fábrica perezosa, para intercambiar el motor open-source por uno patrocinado sin tocar el resto.
  • Grafo del agente propio. Un motor de grafo mínimo (estilo LangGraph, sin LangChain/ LangGraph) orquesta las iteraciones agente ↔︎ tools (ver Agente).

Si un municipio no tiene datos, la UI muestra un aviso (“De momento no tenemos datos de [categoría] para [municipio]…”) y filtra dinámicamente los selectores.

2.5. Selección de base de datos (gotcha importante)

sina.config.credentials.get_db_url() devuelve una URL de PostgreSQL cuando están definidas todas las variables DB_HOST, DB_NAME, DB_USER, DB_PASSWORD; si falta alguna, cae a SQLite (datos/db/sina_data.db).

Puntos a recordar:

  • DB_URL se resuelve al importar el módulo, y repository.py construye un único engine global y llama a Base.metadata.create_all(...) en import-time. Es decir, el destino de la base queda fijado en el momento en que se importa cualquier módulo bajo sina.db.
  • Por eso hay que definir el .env (copiado de .env.example) antes de importar cualquier cosa de sina.db.
  • SQLite quedó como fallback de desarrollo. El volumen de datos de ubicaciones/localidades lo hizo inviable en serio; PostgreSQL aguanta el volumen y pgvector habilita la búsqueda semántica de productos.
